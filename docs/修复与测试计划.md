# SignalInsight 修复与验证计划

> 依据:2026-10-01 全项目审计(核心链路 + UI 层 + 权限/构建层,含 Android 官方文档取证与真机实测)
> 原则:**一次只改一个变量**、**每批可回滚**、**无证据不下结论**

---

## 0. 五条铁律

1. **证据三件套**:任何结论必须同时有 ① 过滤后的 logcat ② 截图 ③ 系统侧原始数据(`dumpsys`)三者中的至少两项。
2. **真值优先于 UI**:App 显示值必须与系统侧 `CellInfo` 原始值交叉验证,不做"看起来对"的判断。
3. **性能只在 release 上测**:debug 不混淆、体积大、行为不同;性能类结论一律基于 `assembleRelease` 产物。
4. **A/B 对比优于单点观测**:涉及行为改变的批次(尤其核心链路迁移),同一地点同一时刻交替安装新旧 APK,采 60s 序列做分布对比,不看单帧。
5. **未证实就写"未证实"**:真机复现不了的,计划里标注条件,不升级为结论。

## 1. 测试脚手架

### 1.1 证据目录

```
%TEMP%\si-verify\
  ├── apk\            # 每批构建的 APK 快照(batchA.apk / batchC-before.apk …)用于 A/B
  ├── <时间戳>-<场景>\  # 每次运行的原始证据
  │     ├── logcat.txt        # 按 TAG 过滤
  │     ├── logcat-full.txt
  │     ├── screenshot.png
  │     ├── dumpsys-telephony.txt   # 系统侧真值
  │     ├── dumpsys-isub.txt        # 订阅/卡槽真值
  │     ├── dumpsys-package.txt     # 权限授予真值
  │     └── notes.md                # 手工观察记录
```

### 1.2 采集脚本(计划实现:`scripts/verify.ps1`)

```
scripts/verify.ps1 -Device <serial> -Scenario <名> -Seconds 60 [-KeepAwake] [-Grant] [-NoLaunch]
```

行为:清 logcat → (可选)授权 → force-stop → 启动 → 保持唤醒 → 等待 N 秒 → 抓 logcat/截图/三个 dumpsys → 落到证据目录并打印摘要。

### 1.3 关键真值命令(已验证可用)

| 目的 | 命令 |
|---|---|
| 原始 CellInfo(rsrp/rsrq/rssnr/bands/nrarfcn/tac/pci/isRegistered) | `adb shell dumpsys telephony.registry` |
| 卡槽 ↔ 订阅映射 | `adb shell dumpsys isub` |
| 权限授予真值 | `adb shell dumpsys package <pkg>` |
| 屏幕常亮(修正上次点击测试因息屏失败) | `adb shell svc power stayon true` / `input keyevent KEYCODE_WAKEUP` |
| 深色模式 | `adb shell cmd uimode night yes|no` |

### 1.4 本机环境坑(已踩,务必遵守)

| 坑 | 现象 | 对策 |
|---|---|---|
| shell 是 **Windows PowerShell 5.1**(无 PS7) | 执行策略 Restricted → 脚本无法直接运行 | 必须 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify.ps1 ...` |
| PS 5.1 对**无 BOM** 的 UTF-8 脚本按 ANSI 解析 | 脚本内中文字面量被读错 → 日志关键词统计恒为 0 | `scripts/verify.ps1` **必须保存为 UTF-8 带 BOM** |
| 脚本参数命名为 `$Args` | 与自动变量 `$args` 冲突,splat 展开为空 → adb 只打印帮助 | 参数名用 `$AdbArgs` |
| `$ErrorActionPreference="Stop"` + 原生命令写 stderr | 脚本被中断(如 `adb pull` 的进度行) | 用 `Continue`,显式 `throw` 处理真正的失败 |
| MIUI/HyperOS 的「USB 安装」限制 | 新包安装报 `INSTALL_FAILED_USER_RESTRICTED`;**更新**已装包却可以 | 需要用户在开发者选项里开启;或改用 `pm clear` 重置数据以避免重装 |
| 手机息屏 | 截图全黑、`input tap` 无效 | `svc power stayon true` + `KEYCODE_WAKEUP`(已内置到 `-KeepAwake`) |
