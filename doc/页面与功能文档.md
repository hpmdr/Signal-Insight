## 3. 页面详解

### 3.1 权限授权页（PermissionScreen）

**入口**：应用启动时若权限未齐备，`MainActivity` 直接渲染本页（不进入 NavHost）。

**页面元素**

| 元素 | 说明 |
|------|------|
| 副标题 | 「请授权以下权限以使用基站信号监测功能」 |
| 权限卡片 ×2 | 电话权限、精确位置权限；每张显示标题、用途、状态 |
| 状态文案 | `已开启` / `待授权` / `需手动开启` |
| 主按钮 | `授权并进入`（常规）或 `去设置中心`（存在永久拒绝时） |
| 提示条 | 存在永久拒绝时显示「部分权限被永久拒绝，请在设置中手动开启」 |

**请求的权限（运行时）**

| 权限 | 必要性 | 说明 |
|------|--------|------|
| `READ_PHONE_STATE` | 必需 | 读取运营商、网络类型、订阅信息 |
| `ACCESS_FINE_LOCATION` | 必需 | Android 要求读取基站信息须有位置权限 |
| `ACCESS_COARSE_LOCATION` | 随 FINE 配对请求 | **官方要求**：不得单独请求 FINE，必须与 COARSE 在同一次请求中提交，否则部分 Android 12 版本会忽略整个请求 |

> `READ_BASIC_PHONE_STATE` 在 manifest 中**声明**（供 Android 13+ 的 `getDataNetworkType()` 使用），但**不列入运行时请求**——官方定义它是 non-dangerous 权限，安装即授予，用户无法开关。

**判定逻辑**

```
已授权        = checkSelfPermission(GRANTED)
永久拒绝      = 未授权 且 曾经请求过 且 shouldShowRequestPermissionRationale=false
```

「曾经请求过」持久化在 `SharedPreferences(permission_prefs)`，跨进程重启保留——否则重启后会把「永久拒绝」误判为「从未请求」，用户点击授权时系统不弹框也不提示去设置。

### 3.2 信号监测页（CellularPage）

**入口**：抽屉「信号监测」，也是应用主页面。

**布局**

```
Box（全屏）
 ├─ HorizontalPager（2 页，左右滑动切换 SIM）
 │    ├─ Page 0 → SimContentPage(SIM 1 数据)
 │    └─ Page 1 → SimContentPage(SIM 2 数据)
 └─ ElasticSimSwitcher（悬浮底部，叠加在内容之上）
```

**单页内容（`SimContentPage`，无状态组件）**

| 区块 | 内容 |
|------|------|
| 信号环卡片 | dBm 大数字 + 环形进度 + 运营商与网络类型 + 强度标签 |
| 指标网格 | 8 格：RSRP / RSRQ / SINR / RSSI / Band / PCI / EARFCN / TAC |
| 邻小区表格 | PCI / 频点 / 频段 / RSRP / RSRQ / SINR |

**指标标签随网络制式自适应**

| 制式 | RSRP 列 | RSRQ 列 | SINR 列 | RSSI 列 |
|------|---------|---------|---------|---------|
| 5G NR | SS-RSRP | SS-RSRQ | SS-SINR | 无数据（NR 无此概念） |
| 4G LTE | RSRP | RSRQ | SINR | RSSI |
| 3G WCDMA | 无数据 | 无数据 | 无数据 | 无数据 |
| 2G GSM | 无数据 | 无数据 | 无数据 | RSSI |

**SIM 切换栏（`ElasticSimSwitcher`）**

- 悬浮半透明胶囊，双边界弹簧动画（液滴拉伸吸附效果）
- 显示两张卡的运营商名；无卡槽显示本地化「未插卡」
- 点击切换，或左右滑动 Pager 切换；**两种方式双向同步**
- 手动选择后被**完全尊重**，不会被自动切走（见下）

**卡槽选择策略**

| 时机 | 行为 |
|------|------|
| 首次拿到有效数据 | 自动选择一次默认卡槽：仅卡 2 有卡则选卡 2，否则选卡 1 |
| 之后 | 完全由用户决定，**不再自动切换** |

**响应式布局**

| 条件 | 布局 |
|------|------|
| 宽度 > 600dp（横屏/平板） | 信号环与指标网格**左右双列**，间距压缩 |
| 否则 | 纵向排列 |

**数据刷新**

- 被动：`TelephonyCallback.CellInfoListener` 监听基站变化
- 主动：前台每 **2s 或 5s**（用户可选）调用 `requestCellInfoUpdate()`
- 结果统一经 `CellInfoListener` 抵达，不改变下游链路
- 邻区列表按 RSRP 降序；**不可用值排在最后**

### 3.3 信号综合概览页（SignalOverviewScreen）

**入口**：点击信号环（`MetricKey.OVERVIEW`）。

**页面元素**

| 区块 | 内容 |
|------|------|
| 评分环 | 0–100 分，Energy Pulse 动画（数字跳跃 + 弹性弹跳 + 脉冲波纹）；颜色随评级变化 |
| 评级标签 | 优秀 / 良好 / 一般 / 较差 / 极弱 |
| 诊断文本 | 由 `SignalQualityEvaluator` 生成的自然语言说明 |
| 短板建议 | 「💡 …」形式，针对评分最低的可用参数 |
| 参数速览卡 | 各指标的分项得分与一句话说明 |

**评分权重（按制式差异化，分母只统计**实际可用**的参数）**

| 制式 | 权重构成 |
|------|---------|
| 5G NR | RSRP 40% + RSRQ 25% + SINR 35% |
| 4G LTE | RSRP 35% + RSRQ 20% + SINR 30% + RSSI 15% |
| 3G WCDMA | dbm 100% |
| 2G GSM | dbm 40% + RSSI 60% |

> **关键设计**：某参数在当前网络制式/机型下不可用时，**不参与加权**（分母同步缩小），而不是记 0 分。
> 否则会出现「RSRP 优秀 + RSRQ 良好、但 SINR 未上报」被算成 59 分「一般」的误判（修正前实测值）。

**评级阈值**：优秀 ≥80、良好 ≥60、一般 ≥40、较差 ≥20、极弱 <20

### 3.4 指标科普页（8 个）

统一结构（`ExplainerUtils` 提供的共享组件）：

```
科普页
 ├─ 顶部：指标名 + 单位 + 当前值（带动态显色）
 ├─ SectionCard「它是做什么的」
 ├─ SectionCard「对体验的影响」
 ├─ SectionCard「参考标准 / 分级表」（表格形式）
 └─ SectionCard「当前评估」（结合当前实测值给出个性化结论）
```

各页特有内容：

| 页面 | 特殊内容 |
|------|---------|
| `RsrpExplainer` | 5 档强度分级表（极佳/良好/一般/较差/极弱）+ 影响因素列表 |
| `RsrqExplainer` | 质量分级 + **RSRP × RSRQ 联合判断**（强+优 / 强+噪声 / 弱+差） |
| `SinrExplainer` | **SINR → 下载速度映射表**（5G/4G 分别给出 Mbps 区间与调制方式）+ 影响因素 |
| `RssiExplainer` | RSSI 与 RSRP 的对比说明 + 何时使用 |
| `BandExplainer` | 当前频段展示 + 5G/4G 频段对照表 + 运营商频段表 + 频段评估 |
| `EarfcnExplainer` | 频率换算公式（4G/NR）+ 运营商频段表 |
| `PciExplainer` | PCI 作用 + 切换机制 + **PCI mod 3 干扰说明** |
| `TacExplainer` | TAC 更新机制 + 用途（寻呼与位置管理） |

**单位与显示规则**：值不可用时（`CellInfo.UNAVAILABLE`）一律显示本地化「无数据」，不做数值渲染。

## 4. 功能清单

### 4.1 信号采集

| 功能 | 实现要点 |
|------|---------|
| 双卡独立采集 | 每张卡一个 `callbackFlow`，通过 `combine()` 合并 |
| 被动 + 主动混合刷新 | Listener 监听 + 定时 `requestCellInfoUpdate()` |
| 频段反算 | EARFCN / NR-ARFCN → 频段查表，覆盖国内主流 LTE（B1/3/5/8/34/38/39/40/41）与 NR（n1/3/5/8/28/41/78/79） |
| MIUI SINR 兼容 | CellInfo 不返回 LTE RSSNR 时，由 `TelephonyCallback.SignalStrengthsListener` 提供备用值 |
| 热插拔监听 | `SubscriptionManager.OnSubscriptionsChangedListener`，换卡后自动重绑监听器 |
| 空数据防抖 | `hasValidEver` 标记，避免网络切换（5G↔4G）瞬间的空 CellInfo 导致 UI 闪「无数据」 |

### 4.2 双卡与订阅

| 功能 | 实现要点 |
|------|---------|
| 卡槽 → 订阅映射 | `SubscriptionManager.activeSubscriptionInfoList` 按 `simSlotIndex` 匹配 |
| 运营商名解析 | 优先 `SubscriptionInfo.displayName/carrierName`，回退 MCC+MNC 查表 |
| 无卡识别 | 订阅 ID 为 `INVALID_SUBSCRIPTION_ID` 时展示「未插卡」 |

### 4.3 信号质量评估

| 功能 | 实现要点 |
|------|---------|
| 综合评分 | 0–100，按制式差异化权重，**分母仅统计可用参数** |
| 评级 | 五档，含配色（明暗双档自适应） |
| 自然语言诊断 | 根据评分与短板生成说明 |
| 短板识别 | 从**可用参数**中取最低分项，生成改善建议 |
| 动态显色 | 评分阈值与配色同源（`SignalQualityEvaluator` + `SignalLevelColors`），信号环 / 指标格 / 邻小区 / 概览页**共用一套** |

## 5. 状态与边界情况

### 5.1 「无数据」的统一约定

Android 用 `CellInfo.UNAVAILABLE`（常量值 **`Int.MAX_VALUE` = 2147483647**）表示「系统未上报」，本应用同样用 `Int.MAX_VALUE` 表示「无数据」。二者同值，因此**渲染层必须显式判等**：

- 判定入口统一为 `isUnavailable(value)` / `displayMetric(value, placeholder)`
- 所有列（含**邻小区的每一列**）都必须判空，否则会显示 `2147483647`
- 颜色判定必须先判不可用，否则 `Int.MAX_VALUE > -85` 为真会被染成「优秀绿」，把「未上报」误传为「信号极好」
- 排序时不可用值**排到最后**，避免因数值最大而被置顶

### 5.2 各制式可用指标

| 制式 | 可用 | 不可用 |
|------|------|--------|
| 5G NR | ssRsrp / ssRsrq / ssSinr / pci / nrarfcn / tac / band | **rssi**（NR 无此概念） |
| 4G LTE | rsrp / rsrq / rssnr(=SINR) / rssi / pci / earfcn / tac / band | — |
| 3G WCDMA | dbm / psc / uarfcn / lac | RSRP / RSRQ / SINR / RSSI |
| 2G GSM | dbm / rssi / cid / lac | RSRP / RSRQ / SINR |

### 5.3 已知的设备/网络差异

| 现象 | 说明 |
|------|------|
| **4G 下邻小区 SINR 显示「无数据」** | 特定小米机型在 LTE 下 CellInfo 的 `rssnr` 恒为 `UNAVAILABLE`（真机实测），属系统未上报，非应用缺陷；**切到 5G 后 NR 的 `ssSinr` 正常上报** |
| 邻区 `rssnr` 全为 0 | 部分机型对邻区上报 `0` 而非不可用，界面忠实显示 `0 dB`。该值在 3GPP 语义下是合法测量值（极差），非哨兵值 |
| 主动刷新次数受限 | 官方文档：`requestCellInfoUpdate` 的更新「will be rate-limited and are not guaranteed」；快速档 2 秒在部分设备上可能达不到 |
| SINR 备用路径 | 仅用于**服务小区**（邻小区不使用，避免所有邻区显示相同值） |

### 5.4 生命周期与资源

| 事件 | 行为 |
|------|------|
| `ON_RESUME` | 启动数据采集 Job + 刷新 Job |
| `ON_PAUSE` | 取消两个 Job，停止监听与轮询 |
| 权限被撤销 | `activeSubscriptionInfoList` / `dataNetworkType` 等调用抛 `SecurityException`，已捕获并降级为「未插卡」/「未知」 |
